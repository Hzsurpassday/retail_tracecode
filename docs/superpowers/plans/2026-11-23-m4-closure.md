# TraceFlow M4 收尾与交付 Implementation Plan（骨架）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **状态：骨架。** 本文件仅固定 M4 范围、顺序与硬约束；每个 Task 的 Files/Interfaces/Step 与验收断言在 M4 启动时按当时的真实代码、M3 合并结果与取证进度逐任务详化（各 Task 下标注 **待 M4 详化**）。骨架不包含任何未实现代码，也不声称任何未验证能力。

**Goal:** 在 M3 零售上传闭环基础上完成路线图 M4：日对账（本地/平台/上游三方 + 上游完整性）、工作台与剩余页面闭环（含追溯码台账）、异常统一队列、CSV 导出防注入、性能基准（NFR-03）、部署与备份恢复手册及演练、2008 R2 实机补验（AT-070）、真实 TOP/G-ERP 取证，以及 ≥7 天试运行与最终交付报告。

**Architecture:** 沿用单体 + 持久任务引擎（outbox_job/租约/fencing）与 Dapper 手写 SQL。M4 新增能力全部以增量迁移（0010+）与独立作业处理器落地，不改写 M0–M3 已交付语义；真实平台发送只在 G-TOP 取证并显式启用后开放，默认仍 fail-closed。前端在现有 React 18 页面上补齐台账/对账/异常队列与导出入口，时间统一 Asia/Shanghai。

**Tech Stack:** .NET 8 / ASP.NET Core 8 / Dapper 2.x / Microsoft.Data.SqlClient 5.x / xUnit / React 18 + TypeScript + Vite 5（沿用 M0–M3；如需新增依赖须单独裁决并说明理由）。

**Spec:** `docs/superpowers/specs/2026-11-22-retail-pharmacy-trace-design.md`（已批设计）。同时必读：`docs/PRD-TraceFlow-单门店-V1.0.md`、`docs/PRD-TraceFlow-验收与代码审查清单.md`（AT-062…064、AT-069…075）、`docs/superpowers/plans/2026-11-22-roadmap.md`、`docs/delivery/M3-gate-report.md`、`docs/delivery/M3-rulings-and-carryforwards.md`、`docs/contracts/openapi.yaml`、`docs/contracts/top-contract.md`、`docs/contracts/data-dictionary.md`、`docs/traceability/matrix.md`。

**分支：** 从 M3 合并后的 `main` 创建 `m4-closure`；M0–M3 已交付语义是既成事实接口，除本计划显式列出的修改点外不得改动。

## Global Constraints

（M0–M3 逐字沿用，M4 不放松）

- 业务库兼容 **SQL Server 2008 R2**：禁止 OFFSET/FETCH、SEQUENCE、JSON_VALUE/OPENJSON、STRING_AGG、temporal table、CREATE OR ALTER、IIF/CONCAT/FORMAT/TRY_CONVERT、THROW、DROP IF EXISTS、TRIM、NOLOCK；分页用 ROW_NUMBER/键集；全部 SQL 在真实 2008 R2 实例验证（AT-070）。
- 数据访问只用 **Dapper + 手写 T-SQL**，不用 EF Core。
- KSOA 源库**只读**；迁移工具只连 TraceFlow 目标库。
- 外部 ID/单号/码一律字符串，索引键列 `COLLATE Latin1_General_BIN2`；数量 `decimal(18,6)`；内部 UTC `datetime2(3)`；`rowversion` 序列化为 16 位大写十六进制字符串；内部 int64 ID 以 JSON number 返回，外部 ID/数量/rowversion 以字符串返回。
- AppKey/AppSecret/连接密码不落 Git、日志、前端、错误响应；凭据 DPAPI 加密；密文不可解密→停调用+告警，无默认凭据兜底。
- 上传状态机按 `UploadStateMachine` 唯一转换表；逐码结果必须含 UNKNOWN；非法转换拒绝并告警。
- 普通测试一律 Fake 平台/fixture；**不得向正式平台上传虚构交易、不得写 ERP 库**；真实平台调用仅限经用户授权的真实业务。
- 匿名拒绝、逐请求权限校验；审计不可变；控制面/人工操作审计 env 恒 `"LIVE"`，自动作业审计 env 用作业 env。
- 前端遵循 NFR-02 React 规范；时间显示 Asia/Shanghai；API 前缀 `/api/v1`；错误统一 `code/message/fieldErrors/retryable/retryAfter/requestId`。
- 未取证能力显示"未接入/未验证"并禁用发送；交付报告不得声称 2008 R2 或真实平台合同已验证。
- **迁移纪律**：0001–0009 字节不可变（checksum 门禁）；M4 DDL 进新增迁移文件（0010 起），新文件以换行结尾；`TreatWarningsAsErrors` 0 警告。
- **测试引擎**（Git Bash，仓库根）：
  `TRACEFLOW_TEST_DB="Server=localhost;Integrated Security=true;Encrypt=true;TrustServerCertificate=true" TRACEFLOW_TEST_DB_ALLOW_NEWER=1 dotnet test traceflow/tests/TraceFlow.IntegrationTests -c Release`
  BIN2 变体追加 `TRACEFLOW_TEST_DB_BIN2=1`；单元测试 `dotnet test traceflow/tests/TraceFlow.UnitTests -c Release`；构建 `dotnet build traceflow/TraceFlow.sln -c Release`；前端 `cd traceflow/src/TraceFlow.Web && npm run build`。
- **提交规则**：每个 Task 末尾提交；`git -c user.name=Hzsurpassday -c user.email=219255064+Hzsurpassday@users.noreply.github.com commit`（不改 git config）；只提交本任务文件；既有未跟踪用户文件一律不动。
- **门禁诚实**：门禁报告只写真实运行输出；矩阵不得引用不存在的测试；M4 新增能力在取证/验证前不得标"已验证"。
