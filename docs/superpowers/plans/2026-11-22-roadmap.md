## 已裁定的对齐决策（写入 ADR-0001）

| 事项 | 决策 | 依据 |
| --- | --- | --- |
| 零售/退货类型 | 销售 321、消费者退货 116（uploadretail）；采购入库 102、采购退货 202（uploadinoutbill） | PRD §8.1；具体传参以 G-TOP 合同验证为准 |
| 上传状态机 | 实现 PRD §9.2 全部 12 态（BLOCKED/READY/DISPATCHING/ACCEPTED/ACCEPTANCE_UNKNOWN/PROCESSING/RETRY_WAIT/PARTIAL_SUCCESS/RESULT_UNRESOLVED/SUCCEEDED/FAILED/MANUAL_ACTION）；设计 §2.6 转换表是其子集，语义一致。设计"已排队"=READY，"发送中"=DISPATCHING，"已受理"=ACCEPTED，"处理中"=PROCESSING，"全部成功"=SUCCEEDED，"部分成功"=PARTIAL_SUCCESS，"结果无法判定"=RESULT_UNRESOLVED，"确定失败"=FAILED，"受理未知"=ACCEPTANCE_UNKNOWN；资格未满足=BLOCKED，转人工=MANUAL_ACTION，可重试等待=RETRY_WAIT | PRD §9.2 + 设计 §2.6 |
| 部署形态 | 单一发布单元（Windows 服务自宿主），同一二进制支持 `--worker-only` / `--web-only` 运行模式；持久队列不依赖进程内存，多实例安全认领 | 用户批准方案 A > PRD NFR-01 默认；JOB-01 多实例要求仍满足 |
| POS 采码状态 | 按 G-POS 门禁：fixture 适配开发，真实销售自动上报禁用直至取得逐盒扫码落库样例 | SCOPE-09 与用户口述冲突，取证据主义 |
| 平台接口全集 | PRD §8.1 表为准（含 getentinfolist、query.listparts、listbillprocesspartsuccess、query.billcount、searchbill、query.upoutbillcount、service.getenddate）；query.relation/querycodeactive 按需启用须合同+权限证据 | PRD §8.1 |
| 数据访问 | Dapper + 手写 T-SQL，全部语句真实 SQL Server 2008 R2 验证；禁 OFFSET/FETCH、SEQUENCE、JSON 函数、STRING_AGG、CREATE OR ALTER 等 | 设计 §1.3、DB-03 |
| 表名 | 物理表按本计划 DDL；交付数据字典给出 PRD §11.2 逻辑实体 → 物理表一一映射（PRD 允许物理拆表，语义与唯一性不缺失） | PRD §11 |

## 阶段划分（每阶段一份独立计划，产出可运行可测软件）

| 阶段 | 计划文件 | 范围 | 关键门禁/验收 |
| --- | --- | --- | --- |
| M0 基础 | `2026-11-22-m0-foundation.md`（本次交付） | 解决方案骨架、ADR、完整 DDL+迁移工具、12 态状态机、bill_code/数量/码规范化值对象、持久任务引擎（认领/租约/fencing/恢复）、认证权限审计幂等、宿主+React 壳、OpenAPI、适配事实矩阵+fixture、需求追踪矩阵 | AT-058/059/065/066/070（引擎与约束部分）；SQL 2008 R2 真实连接证据 |

每阶段计划编写时机：上一阶段完成并通过其验收后，依据实际落定的接口编写下一阶段（避免凭空猜测接口）。所有阶段共用 M0 计划的全局约束。

## 授权边界（全阶段有效）

- 开发授权 ≠ 向正式平台上传虚构交易 ≠ 写 ERP 库。普通测试一律假平台+fixture。
- 真实平台调用仅限经用户授权的真实业务联调；真实 SQL 2008 R2 集成测试使用独立测试库，不触 ksoa 生产数据。
- 不引入 WES、全库商品下载、独立购销扫码页、多门店、强制换号重传。
